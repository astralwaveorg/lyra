# 使用指南

Lyra 的页面按「看内容、修内容、管理系统」分成三组。第一次使用建议按下面的顺序走一遍。

## 第一次使用

1. **只读审计。** 保持 `read_only = true`，打开「音乐」和「文件」，确认曲库规模、格式、歌词状态符合预期。
2. **看概览。** 确认受管根健康、标签覆盖率、歌词覆盖率和问题分布。
3. **小批量试跑。** 在「自动化」里选一个目录，限制数量，先抓取不写入。
4. **审查。** 在「待办 · 歌词」逐首确认来源、行数和时间轴；AI 预审（可选）会给每条候选一个判定建议。
5. **开启写入。** 确认配置和备份目录后，再打开写入开关。
6. **处理标签。** 在「待办 · 标签」先扫描，处理可补与待确认项。
7. **整理目录。** 在「曲库整理」先预览，确认新路径后再执行；也可以开启自动归位让新文件自动就位。
8. **重复音频。** 先检测，按分类查看，最后人工确认删除。

## 待办

维护组第一个入口，六类队列统一收件箱：**歌词 / 标签 / 封面 / 归置 / 孤儿 / 失败**。
点开任何一项都会进入同一个详情抽屉，操作前能看到对象的全部上下文。

- **歌词**：推荐采纳与待审查两个队列，支持批量采用、来源对比、手动刮削；
  开启 AI 预审后，每条候选带「模型判定」标记（同一录音 / 同曲异版 + 置信度）。
- **封面**：缺封面的曲目清单，可逐个打开详情手工处理；批量补封面在「自动化」页。
- **归置**：自动归位的冲突与建议（归置模式默认不动任何文件）。
- **失败**：写入失败与任务失败集中在这里，网络类失败可一键重试。
- **孤儿**：没有对应音频的歌词文件，含 AI 判重。

## 自动化

流水线控制台，三个页签：

- **批量任务**：按范围与筛选发起歌词抓取 / 写入，下方是监控心跳。
- **任务历史**：最近 30 次批量任务；入库与抓取任务可展开看「每文件 × 每环节」
  的结果矩阵（身份 / 歌词 / 封面 / 归位），失败项直接进待办。
- **来源健康**：QQ / 网易云 / LRCLIB 最近 30 天的可用性计数。
  「被风控」计数非零说明来源在拦截请求——QQ 可以在配置里指向自建反代网关。

### 入库流水线

新文件被监控发现后自动执行：**身份识别 → 歌词抓取 → 封面嵌入 → 自动归位**。

- 身份识别按证据分级：标签 MBID → 音频指纹 → 目录锚点 → 搜索；脏文件名
  （`01 - 艺人 - 歌名`、版本标记）会被解析成查询线索。
- 封面：同目录规范命名图片（cover.jpg 等）自动嵌入；有发行 MBID 时从
  Cover Art Archive 按专辑一次下载。MP3 / OGG / Opus 均可写封面。
- 自动归位默认关闭；`policy.organize.mode = "new_files"` 后仅对新增文件
  按模板建目录移动，冲突转待办，全部移动可在「活动」页撤销。存量曲库
  永远在「曲库整理」页人工预览执行。
- 任意范围可手动重跑：`POST /api/v1/tasks/ingest` 或自动化页任务表单。

## 概览

概览页展示曲库规模、时长、专辑/艺人数、歌词覆盖率、标签完整度、流派和时长分布，以及待处理入口。

- 「重新统计」会强制重新扫描；首次统计在 NAS 上可能需要几秒到几十秒。
- 「写入进度」只统计最近 60 天。
- 「待处理」里的数字可以点进对应页面。
- 侧栏底部的「监控运行中 / 监控无心跳」来自监控进程的心跳。只运行 Web 不运行 `lyra watch` 时显示无心跳是正常的。

## 音乐

按路径搜索，按问题、歌词状态和来源过滤。每一行显示歌词文件状态、内嵌歌词状态和问题标签。

- 点问题标签进入修复面板。
- 「详情」查看标签、歌词、封面和文件信息。
- 支持分页，默认每页 50 首。
- 问题码包括缺歌词、缺内嵌、缺 `.lrc`、歌词名不符、容器与扩展名不符、缺封面、缺 MBID 等。

## 文件

按文件类型浏览音频、歌词、图片和文本。可以多选后移入回收站。

- 删除是移动，不是 unlink。
- 音频删除时，同名 `.lrc` 会一起移走。
- 图片、歌词和文本可以预览。
- 不建议在这里整理目录；目录整理用「曲库整理」，因为它有预览和撤销。

## 待办 · 歌词

歌词队列在待办页内，内部三个标签：

- **推荐采纳**：所有硬性条件通过，只是分数没有达到自动接受线。可以批量或逐首采用。
- **待审查**：需要人工确认。可以对比来源、看逐行差异、播放音频。
- **无音源**：没有对应音频的歌词文件，通常是放错目录或改名残留。

写入前会显示将写入的字段、来源和差异。人工确认的写入默认做完整备份。

每页显示多少首可切换（20 / 50 / 100 / 200），默认 20。同一首歌的多个来源
候选按**分数从高到低**排列，第一条就是系统推荐的那条。

两个标签都支持**勾选批量采用**：每行（待审查按整首卡片）有勾选框，
配「全选本页 / 清除选择 / 批量采用」。勾住一首 = 采用它的推荐候选
（分数最高的那条），同一首的其它候选会被自动驳回。翻页或刷新后勾选清空，
不会把看不见的行带进批量。待审查里被硬性条件拦下的项（例如翻唱导致
艺人对不上）也能这样成批采用——勾选本身就是人的判断。

**忽略是持久的**：单首的「忽略」和勾选后的「批量忽略」都会为曲目写一条
排除规则，之后的自动抓取与监控不再为它取词，它也不会再回到队列。反悔入口
在「已忽略」标签：列出全部被忽略的曲目，点「恢复」删掉规则，下一轮抓取
会重新匹配这首歌。

## 自动化 · 批量抓取

选择范围和数量，抓取歌词到暂存区。抓取本身不写音乐文件。

- 「立即写入」把暂存歌词写入音频和 `.lrc`。
- 可以按**艺人**筛选：单选，包含即命中（多艺人署名命中其中任意一个）。
- 任务在后台执行，可以离开页面；进度和心跳会显示。
- 自动监控也会按间隔执行同样的流程。
- 已有有效同步歌词默认跳过，不会反复覆盖。

### 单曲手工选词与歌词编辑

在音乐库页对某一首点「刮削歌词」，可以列出各来源的候选、逐条预览，然后「采用并写入」。

- 文件里已经有歌词时，服务端会要求先勾选「覆盖已有歌词」才允许替换；替换前会完整备份原文件。
- 人工选定的那一条**一定会写进去**：即使它没有时间轴（纯文本歌词）也照写。自动流程拒绝纯文本是对的，人看过之后选定就是决定。
- 只写你选中的那一条。同一位置其它历史候选会被作废，不会被批量写入顺手写进去。
- 文件里本来就已经是这份歌词时，**照样重写一次**，回执会说明「已强制写入」。内容一字不差不代表文件是对的——同一首歌的短版常常配着完整版的时间轴，那种情况下「内容一样」的判定会把问题挡住。批量与自动写入不受影响：那里「已经满足就不写」是为了不产生几十 GB 的无意义备份。
- 预览会说明候选歌词的时间轴有没有超出音频时长。超出多半是别的版本的词，建议换一条再写。

### 歌词编辑器

详情抽屉的歌词页签可以**直接编辑歌词文本**并写回内嵌与同名 `.lrc`——修一行、
调一个时间轴不再需要外部编辑器。写入前会确认，写入走完整的备份与撤销链路；
可选粘贴带时间轴的整段翻译，按双语文体合并（由「设置 → 歌词输出」控制）。

## 待办 · 标签

标签队列在待办页内，按「推荐采纳 / 待审查 / 未匹配」分组。

- 扫描会先检查 MusicBrainz 是否可用；不可用时不会把全库标成未匹配。
- 每首曲目显示逐字段对照：本地值、来源值、判断。
- 「可补」只补空字段；「纠正」按同目录专辑统一发行字段；「冲突」需要人工确认。
- 冲突字段默认勾选，支持全选和取消全选。
- 写入前有确认框，列出字段和影响。
- 写入历史可以按字段撤销。

详见[标签刮削](tags.md)。

## 曲库整理

三个标签页：

### 一键整理

选择受管根、要整理的目录（可多选）和要排除的目录（可多选），生成预览。

- 预览列出每首歌的旧路径、新路径、状态和原因。
- 状态包括移动、已正确、目标冲突、无法生成路径。
- 目标已存在的文件不会覆盖，会标成冲突。
- 移动后为空的目录会列出来，默认勾选清理。
- 只有点击「执行」才会真正移动。

命名规则和重复处理见[曲库整理](organize.md)。

### 重复音频

按证据分为三类：

| 分类 | 判定 | 处理建议 |
| --- | --- | --- |
| 音频完全一致 | 去掉标签后的音频哈希相同 | 通常可以直接保留一份 |
| 同一录音 | MusicBrainz 录音 ID 或 AcoustID 指纹相同 | 可能是不同压缩或版本，试听后决定 |
| 标题/艺人/时长相近 | 标题、艺人相同，整组时长跨度不超过 2 秒 | 不一定同一录音，必须试听 |

每张卡片显示格式、时长、大小、标题、艺人、专辑、路径和保留理由。建议删除的副本默认不勾选；可以逐项选择、全选当前分类，或按分类一键删除。

参照项标为「其他分类保留」，不参与删除。删除前会再次确认分类和数量。

### 空目录

扫描曲库中的空目录，预览后移入回收站。刚被填入文件的目录不会被当成空目录。

## 回收站

按批次查看移入回收站的文件。可以还原或永久删除。

- 还原会保留原相对路径。
- 永久删除不可恢复。
- 回收站位于 `data/trash/`，不会自动清理。

## 日志

三个标签页：

- **写入**：歌词和标签写入记录，可以按字段撤销。
- **改名**：文件改名记录，可以逐条撤销。
- **整理**：移动、删除和空目录清理记录，支持多选批量撤销。

撤销按时间倒序执行。单条失败不会阻止其他条目，失败原因会显示在结果里。

## 设置

- **账户**：登录状态、退出登录。
- **外观**：深色/浅色，跟随系统。
- **标签刮削**：自动扫描、间隔、自动写入、指纹、单轮上限、时长容差。
- **修改密码**：至少 10 位。
- **API 令牌**：给脚本和移动端签发 Bearer Token，明文只显示一次。
- **运行信息**：版本、数据库结构、写入开关、来源和受管根。

设置页保存的标签策略会写入数据库，并覆盖配置文件里的 `[policy.tags]`。监控进程每分钟检查一次变更。

「大模型」支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages 三种协议。可以填 base URL 或完整 endpoint，保存前可用「测试连接」发一条最小请求。Token 只保存在服务端 `data/ai-token`，页面不会回显完整值。

## 键盘与移动端

界面在桌面和手机上使用同一套路由。手机上侧栏变成抽屉，表格变成卡片列表，操作按钮保留在卡片内。歌词对比和整理预览在窄屏下改为纵向排列。
