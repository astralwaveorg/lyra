# 标签刮削

标签刮削用 MusicBrainz 补齐曲库缺失的元数据，并在写入前把每个字段的判断摆出来。

## 匹配顺序

1. **MBID。** 文件已有 `MUSICBRAINZ_TRACKID` 时直接查录音，最可靠。
2. **目录共识。** 同一专辑目录里的曲目共享发行信息时，用多数结果补发行级字段。
3. **标题搜索。** 用标题、艺人、专辑和时长组合搜索，按分数和时长闸门筛选。
4. **AcoustID 指纹。** 缺 MBID 或搜索有歧义时，用音频指纹确认录音。

候选必须通过硬性闸门：

- 时长差不超过 `policy.matching.max_duration_delta_seconds`，默认 5 秒。
- 标题、艺人、版本信息不能明显冲突。
- 最优候选与次优的分差达到 `min_score_margin`，除非时长差很小。

不满足时进入「待审查」，不会猜。

## 字段判断

每个字段只有四种结果：

| 结果 | 含义 | 默认行为 |
| --- | --- | --- |
| `same` | 本地与来源相同 | 不写 |
| `fill` | 本地为空，来源有值 | 可自动写入 |
| `correct` | 发行级字段，按同目录专辑统一 | 可批量写入 |
| `conflict` | 两边都有值且不同 | 默认勾选，人工确认 |

「纠正」只用于发行级字段，例如专辑、日期、厂牌、目录号、发行类型、介质、总轨数。标题、艺人、作词作曲等字段不会因为目录共识被批量覆盖。

## 冲突处理

冲突字段默认勾选，表示「采用来源值」。可以：

- 逐字段取消勾选；
- 一键全选；
- 一键取消全选；
- 只写「可补」和「纠正」，跳过冲突。

写入前的确认框会列出字段、来源值和影响。标题、艺人、专辑等关键字段发生变化时会额外提示。

以下情况仍会进入人工复核：

- 版本不同，例如现场版、重制版、伴奏版。
- 本地多出合作艺人，或艺人名单明显不同。
- 时长差超过标签写入容差。
- 来源本身有歧义。

## 批量写入

待审查列表支持勾选多条后一次写入：

- 行首勾选框选中单条；组头勾选框整组全选；「全选本页」选中当前页所有可写条目。
- 「写入所选（N）」按每行的建议一次性写入，冲突也一并覆盖——逐行勾选就是人工确认，
  与单条展开后写入同口径。确认框会列出补空、纠正和覆盖冲突的数量。
- 标题搜索来源的条目不参与批量，请逐条确认；只读格式和没有可写字段的条目不可勾选。
- 翻页或切换页签会清空勾选，不会把看不见的条目带进批量。
- 单条写入失败（例如文件在扫描后被其他工具改动）只记入结果里的错误列表，不影响其余条目。
- 「写入本页可补」仍然只写补空与纠正，不覆盖冲突；需要保守处理时用它。

## 自动扫描与自动写入

监控进程按 `scan_interval_hours` 扫描全库。设置页可以修改间隔、自动写入、指纹和单轮上限，保存后一分钟内生效。

自动写入只做两件事：

- 补本地为空的字段；
- 按可信目录簇纠正发行级字段。

冲突永不自动覆盖。单轮写入数量受 `max_auto_write_per_run` 限制。

## 写入安全

- 只改目标字段。音频数据、封面、歌词、作词人、未知标签保持不变。
- FLAC 使用 Vorbis comment 块级改写；MP3 使用 ID3v2 目标帧改写；OGG 重排 comment 页。
- 写入前备份；写入后校验音频哈希和非目标标签。
- 校验失败自动回滚，并保留失败原因。
- 撤销按字段恢复原值，不会把整份标签覆盖回旧版本。

## 按链接指定

「按链接指定」支持 MusicBrainz 的发行、录音、发行组和艺人链接。查询只读，不会改文件。

适合以下情况：

- 自动搜索没有命中；
- 同名曲目太多；
- 想指定某个发行版或某个现场版本。

链接会校验域名必须是 `musicbrainz.org` 或其子域，避免 SSRF。

## 人工确认与忽略

队列里每一条都可能是人已经表过态的，所以人工决定必须留得住：

- **按链接指定**是人工断言「就是这一条」。指定之后，自动扫描不会再用搜索结果覆盖它。
- **写入完成**（所有待处理字段都写完）后，提案标记为「已定案」，不再出现在待审查与未匹配里，
  下一轮扫描也不会把它带回来——哪怕来源算出来的结果跟上次不同。
- **忽略**把条目移出队列，扫描同样不会再翻它出来。忽略掉的条目在「已忽略」页签里，
  随时可以「恢复」放回待审查。

自动扫描只在「没有人工痕迹」时才会重写提案：来源是搜索或目录推定、且没有人处理过的条目，
每轮扫描都可以重新计算。

## 写入历史与撤销

每次写入记录文件名、写入时间、变更字段、原值和新值。可以在标签页的「写入记录」里逐条撤销。

撤销只还原这次写入涉及的字段。如果之后有人手动改过同一字段，撤销会跳过或提示冲突，不会盲目覆盖。

## 常见问题

**扫描显示 MusicBrainz 未配置。**

检查 `providers.musicbrainz.enabled` 和 `base_url`。默认是 `https://musicbrainz.org`；容器内能访问公网即可。

**扫描全部未匹配。**

先确认 MusicBrainz 是否可达。Lyra 在扫描前会做健康检查；不可用时会拒绝扫描，避免把上一轮结果覆盖成未匹配。

**自动写入没有发生。**

检查写入开关、`auto_write`、单轮上限和时长容差。冲突字段永远不会自动写入。

**MP3 的 MusicBrainz ID 读不出来。**

确认文件里是 UFID 帧或对应的 TXXX 帧。Lyra 会读取 UFID 的原始字节并解码为 UUID。
